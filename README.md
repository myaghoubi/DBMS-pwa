# DBMS-pwa — مدیریت سیستم‌های اطلاعاتی

برنامهٔ PWA فارسی: فرم‌ساز، گزارش و نمودار، کاربران و نقش‌ها، فرآیند، اتصال به بله و تلگرام.

## مدیریت نسخه

هر تغییر باید یک نسخهٔ مشخص (`x.y.z`) داشته باشد. منبع نسخه سه جا هم‌زمان نگه‌داری می‌شود و ابزار زیر آن‌ها را با هم تغییر می‌دهد:

| فایل | محتوا |
|---|---|
| `version.js` | **تنها منبع شمارهٔ نسخه** (`APP_VERSION`، `APP_DATE`). `index.html` آن را با `<script>` و `sw.js` با `importScripts` می‌خوانند |
| `changelog.json` | تاریخچهٔ تغییرات (جدیدترین اول) |
| `version.json` | خروجی خودکار برای سازگاری با نسخه‌های ≤ ۰.۴.۰ که فقط این فایل را می‌شناسند؛ دستی ویرایش نشود |

شمارهٔ نسخه دیگر داخل `index.html` یا `sw.js` نوشته نمی‌شود. تغییر `version.js` باعث می‌شود مرورگر `sw.js` را هم جدید ببیند و نسخهٔ تازه را دریافت کند.

### انتشار نسخهٔ جدید

```bash
node tools/bump.mjs patch "رفع اشکال فلان"            # 0.3.0 → 0.3.1
node tools/bump.mjs minor "قابلیت جدید" "یادداشت دوم"  # 0.3.0 → 0.4.0
node tools/bump.mjs major "تغییر ساختار"               # 0.3.0 → 1.0.0
node tools/bump.mjs 1.2.3 "نسخهٔ دلخواه"
node tools/bump.mjs patch "یادداشت" --tag             # ساخت تگ git با نام v<نسخه>
node tools/bump.mjs --check                           # بررسی هم‌خوانی نسخه در سه فایل
```

سپس commit و push (یا deploy) کنید. `version.js` و `changelog.json` باید همیشه روی سرور در دسترس باشند.

### بروزرسانی داخل برنامه

- برنامه هنگام اجرا، هنگام بازگشت به برنامه و به‌صورت دوره‌ای (پیش‌فرض: هر ساعت؛ قابل تنظیم در «تنظیمات برنامه») `version.js` را (و برای نمایش تغییرات `changelog.json` را) از سرور می‌خواند.
- اگر نسخهٔ جدیدتر بود، بنر «نسخهٔ x آماده است» نمایش داده می‌شود و نشانگر قرمز کنار منو و «بروزرسانی» ظاهر می‌شود.
- هیچ بروزرسانی بدون اجازهٔ کاربر انجام نمی‌شود: کاربر تغییرات را می‌بیند و «بروزرسانی اکنون» یا «بعداً» را انتخاب می‌کند. با «بعداً»، برای همان نسخه دوباره بنر نمی‌آید (صفحهٔ «بروزرسانی» همچنان نسخهٔ جدید را نشان می‌دهد).
- هنگام تأیید، سرویس‌ورکر جدید دریافت و فعال می‌شود و برنامه یک‌بار بارگذاری مجدد می‌شود. داده‌های ذخیره‌شده حفظ می‌شود.

## فونت

وزیرمتن از Google Fonts بارگذاری و کش می‌شود. برای آفلاین کامل، فایل `fonts/Vazirmatn-variable.woff2` را اضافه کنید (`fonts/README.txt`).

## آیکون‌ها

آیکون‌ها از [Lucide](https://lucide.dev) (مجوز ISC) هستند و در فایل `icons.js` داخل خود برنامه قرار دارند، پس بدون اینترنت و CDN کار می‌کنند. برای افزودن آیکون، نام و محتوای SVG آن را در شیء `P` همان فایل اضافه کنید. آیکون دکمه‌ها از جدول `LABEL_ICONS` در `index.html` و بر اساس برچسب دکمه تعیین می‌شود.

## جمع‌آوری اطلاعات با ربات تلگرام

1. در «تنظیمات تلگرام» توکن را وارد و ذخیره کنید، سپس «شروع دریافت» را بزنید.
2. لینک ربات (`https://t.me/<ربات>`) را برای افراد بفرستید. با `/start` عضو ربات می‌شوند و در «مشترکین» دیده می‌شوند.
3. فرم را در «ساخت/ویرایش فرم» با گزینهٔ «در ربات تلگرام قابل پر کردن باشد» فعال کنید، یا از «مدیریت فرم‌ها» دکمهٔ «ارسال به تلگرام» را بزنید تا فرم برای مشترکین فرستاده شود. هر فرم یک لینک مستقیم هم دارد: `https://t.me/<ربات>?start=f_<شناسهٔ فرم>`.
4. ربات فیلدها را یکی‌یکی می‌پرسد (دکمه برای انتخابی‌ها، متن برای بقیه، با اعتبارسنجی) و زیرفرم‌ها (تک‌رکوردی و چندرکوردی) را هم پشتیبانی می‌کند. دستورها: `/forms` فهرست فرم‌ها، `/cancel` لغو، `/skip` رد کردن فیلد اختیاری، `/stop` لغو عضویت.
5. پاسخ‌ها در «رکوردها»ی همان فرم، با برچسب «ثبت‌شده از تلگرام»، ذخیره می‌شوند.

**محدودیت:** دریافت پیام‌ها از داخل برنامه (long polling) انجام می‌شود، پس فقط تا وقتی برنامه باز است فعال است. پیام‌های رسیده در زمان بسته‌بودن برنامه تا حدود ۲۴ ساعت نزد تلگرام می‌مانند و با باز شدن برنامه پردازش می‌شوند. برای دریافت دائمی باید یک سرور واسط (webhook) اضافه شود. فقط یک نمونه از برنامه می‌تواند هم‌زمان پیام دریافت کند.
